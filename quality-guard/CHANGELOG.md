# Changelog

All notable changes to quality-guard. Semver; every published change bumps the patch number.

## 0.1.1

### Verification discipline

- Hold unsafe outward delivery/activation when a required check is unavailable, including unattended work. Escalate the specific gap; continue unrelated authorised work.
- Treat the footer as a self-report, not execution proof. Execute the actual CLI/artefact; distinguish source, built/installed, native-host and live integration evidence.
- Independently check destructive-action ownership/blast radius. Repair generating sources, rebuild and recheck final facts/bytes after style or assembly changes.
- Use available tools and authoritative documentation for the installed/pinned version. Supplied material establishes source fidelity, not automatic external factual truth.
- Delegate only demonstrated domain-gate coverage. Preserve generic concurrency, package/index and exact-byte safeguards, without private integration recipes or estate policy.
- Keep operator records separate from client content without concealing recipient-facing limitations. Retain legitimate qualifications and requested multilingual output.

### Optional mechanical helper

- New standard-library-only Python 3.8+ `lint`, `run` and `verify` commands. Every result explicitly leaves `readiness: not_assessed`; no truth detector, automatic send hook, language blacklist or estate-parity checker.
- Check terminal filled records and obvious leakage into supported client text/Markdown/simple HTML. Explicit encoding/format/size errors; ASCII-safe JSON for Windows pipes.
- Run only an explicit approved argument vector, without shell/stdin. Refuse bad inputs/existing receipts before execution; monitor timeout/output limits and terminate the owned child tree headlessly.
- Record actual completion/exit status, output hashes/counts and before/after artefact manifests, never raw argv/output. Verify only explicitly approved receipt/artefact inputs; detect failed/incomplete checks and changed final bytes.
- Document that receipts are forgeable local records, not authentication or proof of semantic readiness; the runner is not a sandbox or detached-process containment system.
- Independent review added regressions for excessive JSON nesting, special-file hangs and uncapped reads. Return structured input errors, reject non-regular text/receipt files and cap the actual read, not only metadata size.
- Correct the process boundary: completion/output accounting is direct-child-only. Explicit scope fields are required in receipts; any ordinary or detached descendant surviving its parent remains unassessed. Commands must wait for their own checks; no process-tree completion claim.

### Packaging and documentation

- Short, discoverable frontmatter; consistent patch-only version bump. Declare both helper and offline suite in the installer manifest, with `verify_skill` installation checks.
- Expanded human README: scanned Hub/tap installation, command examples, formats, privacy, exit codes, limits, acceptance and troubleshooting. Support files are explicitly linked for complete URL installs.
- [VERIFICATION.md](VERIFICATION.md) records executed platform/guard qualification separately from simulation, semantic readiness, publication and rollout.
